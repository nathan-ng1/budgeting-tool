# Categorisation runs through a scripted entry point with a pluggable model backend, not an improvised chat step

Categorising a Statement Export transaction (assigning Category/Sub-category, flagging Needs Review) now runs through `uv run python -m statement_export`, driven by a `Categoriser` interface (`src/categorisation/interface.py`) with three concrete backends — Claude Code (`claude -p`), Codex CLI (`codex exec`), and a generic OpenAI-compatible HTTP endpoint (covering local Ollama and hosted providers) — selected via `CATEGORISER_BACKEND` in `.env`. The script drives the whole flow end to end: parse, categorise, resolve Needs Review through a terminal prompt loop, expand due Recurring Transactions, dedupe, write, archive.

This reverses the framing in earlier drafts of `docs/agents/statement-export-pipeline.md`, which held that categorisation "isn't scripted... it's Claude's job each run" — unlike [ADR-0001](./0001-sanitising-happens-outside-claudes-read-access.md), [ADR-0002](./0002-recurring-schedule-expansion-happens-in-a-script.md), and [ADR-0003](./0003-beem-direction-and-row-filtering-happens-in-the-sanitising-script.md), which all keep something *deterministic* out of Claude's hands, categorisation is a genuine judgement call (is this Square charge a donation or a coffee?) that a fixed rule set can't make reliably — so it stays delegated to a model. What changes is that the surrounding orchestration (which file, which transactions, which categories are even valid, what to do with the model's answer) is no longer improvised turn-by-turn in a chat session; it's the same script regardless of which model is doing the judging. This was a deliberate trade-off, not a deterministic-vs-judgement call: it buys three things a chat-only flow couldn't — running without Claude Code installed at all (a free local Ollama model is enough), running Claude as a backend without incurring separate per-token API billing on top of an existing subscription, and a single abort-on-malformed-output contract that behaves identically no matter which model produced a bad response. The cost is that every backend must agree on one structured JSON contract (`categorisation/prompt.py`) instead of Claude being free to reason and act inline; a malformed response now aborts that file's run entirely rather than being caught mid-conversation.
